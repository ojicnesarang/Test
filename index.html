STEP 1

STEP 2
카카오 로그인

        
카카오 JS SDK v2에는 팝업 로그인 함수(Auth.login)가 없어, ‘카카오 로그인’을 누르면 카카오 로그인 페이지로 이동했다가 인가 코드를 갖고 이 페이지로 돌아오는 방식으로 동작합니다. 돌아온 뒤에는 REST API 키로 인가 코드를 액세스 토큰으로 교환합니다. REST API 키도 JavaScript 키와 마찬가지로 이 페이지의 메모리에서만 쓰고 어디에도 저장하지 않습니다. 버튼을 누르면 시도 과정이 아래 ‘로그인 응답’에 그대로 기록됩니다. 앱 안 웹뷰처럼 페이지 이동이 막히는 환경에서는 아래 방법 B(외부 브라우저로 로그인)를, 토큰 교환 응답을 페이지 안에서 읽지 못하는 환경에서는 방법 C(폼으로 토큰 받기)를 사용해 주세요.

        

          
          
          
          로그아웃 상태
        

        
‘카카오 로그인’을 누르면 카카오 로그인 페이지(kauth.kakao.com)로 이동합니다. ‘웹페이지 사용할 수 없음’ 화면이 뜨면 앱 안 웹뷰가 그 이동을 막은 것이니, 뒤로 가기로 이 페이지로 돌아와 아래 방법 B로 진행해 주세요.

        

          카카오 로그인 페이지로 이동하지 못했습니다.

          버튼을 누른 뒤 6초가 지나도 이 페이지에 그대로 있는 상태입니다. 이 환경(앱 안 웹뷰)에서는 카카오 인가 페이지로 이동이 막혀 있는 것으로 보입니다. 아래 방법 B — 외부 브라우저로 로그인으로 진행해 주세요.
        

        

        

          동의항목 talk_message — 카카오톡 메시지 전송
          동의항목 friends — 카카오톡 친구 목록 조회
        

        
로그인 후 돌아올 주소(Redirect URI)입니다. 카카오 콘솔에 ① 카카오 로그인 > Redirect URI에 이 주소 전체, ② 플랫폼 > Web > 사이트 도메인에 이 주소의 도메인이 등록돼 있어야 로그인이 진행됩니다. 등록돼 있지 않으면 카카오 오류 페이지(예: KOE006)가 뜹니다.

        

        

          
          

            
            
          

          
인가 코드를 받은 뒤에만 ‘토큰 교환’ 버튼이 활성화됩니다. 교환은 fetch로 먼저 시도하고, 응답을 읽지 못하면 카카오 SDK가 쓰는 XMLHttpRequest 방식으로 자동 재시도합니다. 키는 교환이 성공한 뒤에만 입력칸에서 지우므로, 실패해도 키를 다시 입력하지 않고 바로 재시도할 수 있습니다. 두 방식 모두 응답을 읽지 못하는 환경이면 아래 방법 C를 사용해 주세요.

        


        

          
방법 B — 외부 브라우저로 로그인 (웹뷰에서 이동이 막힐 때)

          
이 페이지 안에서 카카오 페이지로 이동할 수 없는 환경을 위한 우회 방법입니다. 위 입력칸에 REST API 키를 먼저 넣은 뒤 순서대로 진행해 주세요. 방법 B의 돌아올 주소(Redirect URI)는 카카오 콘솔의 REST API 키에 이미 등록돼 있는 아래 주소를 고정으로 씁니다. 인가 링크 생성과 토큰 교환이 같은 주소를 써야 오류(KOE006)가 나지 않습니다.

          
https://localhost:8080

          
    
            
  1. ‘로그인 링크 만들기’를 누르면 카카오 로그인 링크가 생성됩니다.
    2. 
            
  2. ‘외부 브라우저로 로그인 열기’를 누르면 기기의 기본 브라우저(Chrome 등)에서 카카오 로그인 페이지가 열립니다. 거기서 로그인·동의를 마쳐 주세요.
    3. 
            
  3. 동의 후에는 위 주소(https://localhost:8080)로 이동하려 합니다. 그 주소에서는 페이지가 열리지 않는 게 정상입니다. 브라우저 주소창의 주소에서 code= 뒤 값을 복사해 아래 ‘인가 코드 직접 입력’ 칸에 붙여넣고 ‘코드 적용’을 눌러 주세요. (주소 전체를 붙여넣어도 코드만 자동으로 뽑아냅니다.)
    4. 
            
  4. 이 페이지로 돌아와 STEP 1 연결이 풀려 있으면 JavaScript 키를 다시 입력해 연결한 뒤, 위의 ‘토큰 교환’ 버튼을 누르면 로그인이 완료됩니다. 인가 코드는 1회용이고 유효시간이 짧으니 받은 뒤 바로 진행해 주세요.

방법 C — 토큰 발급 응답을 같은 탭에서 받기 (페이지 안 교환이 막힐 때)

          
‘토큰 교환’을 눌러도 fetch·XMLHttpRequest 모두 카카오 응답을 읽지 못하는 환경용입니다. 폼 제출은 페이지 이동과 같은 방식이라, 교차 출처 응답 읽기 제한(CORS)의 적용을 받지 않습니다. 새 탭(target="_blank") 제출은 안드로이드 웹뷰·크롬에서 제출 본문이 떨어져 파라미터 없음 오류(KOE001)가 날 수 있어, 같은 탭에서 제출하는 방식으로 바꿨습니다.

          
    
            
  1. 위 입력칸에 REST API 키가 들어 있고, 방법 B로 받은 새 인가 코드를 ‘코드 적용’까지 마친 상태에서 아래 ‘방법 C’ 버튼을 누릅니다. 폼 제출도 인가 코드를 1회 소진하니, 앞에서 이미 교환을 시도한 코드로는 하지 마세요. 제출 직전에 보낼 파라미터가 비어 있지 않은지 자동으로 확인하고, 확인 결과(값이 아닌 길이)는 아래 ‘로그인 응답’ 로그에 남습니다.
    2. 
            
  2. 같은 탭이 카카오 토큰 발급 결과(JSON) 화면으로 이동합니다. 그중 access_token 값만 복사해 주세요. 토큰 대신 오류 JSON이 표시되면 코드 소진 등 실패 원인이 그 안에 적혀 있습니다.
    3. 
            
  3. 브라우저 뒤로 가기를 눌러 이 페이지로 돌아온 뒤, 복사한 토큰을 아래 ‘액세스 토큰 직접 입력’ 칸에 붙여넣고 ‘토큰 적용’을 누르면 로그인 상태가 됩니다. 돌아왔을 때 STEP 1 연결이 풀려 있으면 JavaScript 키를 다시 입력해 연결한 뒤 토큰을 적용해 주세요. 이어서 STEP 3·4를 진행하면 됩니다.
    4. 
          

          
진단 안내 — 제출하면 ‘로그인 응답’에 ① 제출 직전 FormData 확인(params_check)과 ② 브라우저가 실제로 전송할 목록(formdata 이벤트)이 함께 남습니다. 둘 다 네 항목이 채워졌는데도 KOE001이 반복되면, 이 페이지가 실행되는 blob: 불투명 오리진 환경이 교차 출처 POST 이동 중 본문을 떨어뜨리는 것이 원인입니다. 그 경우 폼 방식으로는 해결이 안 되고, 내보낸 HTML 파일을 실제 https 도메인(예: www.gianttree-company.com)에 올려 그 주소로 여는 것이 근본 해결책입니다.
